# gmux change audit before publishing

Scope: [67c82c3](https://github.com/mjkpolo/ghostling/commit/67c82c3659d676792a5fed76ef02109a62b6b2dd), its parent [08c24e7](https://github.com/mjkpolo/ghostling/commit/08c24e7e72195e7f976c99d4748751f3c1641d14), follow-up [4a3ebfb](https://github.com/mjkpolo/ghostling/commit/4a3ebfb3e6d5198e14b41f10fafb2df37674fce2), and the unpublished working tree. No push, release, installed-script replacement, or public-server changes were performed by this audit.

## Conclusion first: the health connection

There is **one listening Unix socket per terminal**, not a second health-check listener or SSH forward. `gmuxctl` runs a remote SSH command that invokes `gmux-server --check`; that executable briefly connects to the existing remote terminal socket. Only opening a GUI/preview requests an SSH Unix-socket forward. The manager's SSH ControlMaster socket controls SSH itself, not terminal health.

The extra **accepted connection** in the server exists because its GUI connection may already be occupied. This is justified by a reproduced failure, not by saying “Zellij has sockets too”: with the pre-67 binary and a GUI attached, `--check` timed out and `--kill` returned success without stopping the server. The fixed binary responds while attached. Detailed original lines and the reproduction are in the server ledger below. I kept that capability; I did not add another listener, periodic heartbeat, or health forwarding service.

The original commit mixed useful fixes with precautionary changes and cleanup. It was too broad to justify as simply “following other terminals.” This audit separates those categories and removes unsupported additions. In particular, the later downloader inferred asset URLs from a redirected CDN URL; that inference is now gone. The regression reproduces the wrong URL, **not** the exact HTTP 618 response you reported.

## Evidence rules

- **Reproduced now** means a local audit experiment below actually produced the old failure. It does **not** mean we observed it before writing the original commit. Historical user reports are explicitly separate.
- **Fault injection / modeled event sequence** is marked as such. For example, forcing `realloc` to fail proves the bad cleanup state, not that you previously ran out of memory.
- **Upstream same operation** identifies the exact pinned source, not a numeric similarity claim across unrelated C/Rust/Zig architectures. A loose analogy is insufficient and is not used to defend speculative code.
- **Requested feature / simplifying deletion** is different from unsolicited hardening. Your later editor, versioning, server-owned config, and preview-command requests are kept. Removing a duplicate parser or obsolete font-extraction subsystem does not require inventing a crash or claiming another terminal made the same deletion.
- Unsupported additions are removed rather than relabeled as “best practice.” Audit-only harnesses live under ignored `build/audit/`; they are not shipped in the application.
- Immutable GitHub links identify committed code. Unpublished code has no GitHub permalink; its ledger uses a frozen content hash, quoted expression, and local file/function instead of pretending otherwise.

### The extra health connection

There is **one listening Unix socket**, not a second socket pathname/listener dedicated to health. The `control` variable is a second *accepted connection to that same listener*. It lets the manager's short-lived status/kill command be processed while a GUI occupies the main connection. The main connection still owns the terminal; the control connection only accepts ping/shutdown.

The old server stopped accepting while a GUI was attached ([old listener condition](https://github.com/mjkpolo/ghostling/blob/08c24e7e72195e7f976c99d4748751f3c1641d14/src/server/run.inc#L104)). Reproduced: attach a socket client, run `--check`, then `--kill`. Parent: check took **1.002 s**, kill returned success but left the server/socket running. Commit: check took **0.001 s**, kill removed the socket. The second accepted slot fixes an actual failure, not hypothetical security hardening.

Zellij does essentially the same *operation*: [connect and send ConnStatus](https://github.com/zellij-org/zellij/blob/474ea0cef620c83d6ec05a7c28c7f80c4f63bbbb/zellij-utils/src/sessions.rs#L148), [keep accepting incoming connections](https://github.com/zellij-org/zellij/blob/474ea0cef620c83d6ec05a7c28c7f80c4f63bbbb/zellij-server/src/lib.rs#L946), [reply Connected then remove that temporary client](https://github.com/zellij-org/zellij/blob/474ea0cef620c83d6ec05a7c28c7f80c4f63bbbb/zellij-server/src/lib.rs#L1617). Its implementation is threaded/multi-client, not 90%-identical C. We retain gmux's slot on the **reproduced bug**, not an exaggerated copy claim. No periodic server ping timer is involved.

### Post67 changes and simplification performed during this audit

Server-only font/config snapshots, font delta messages, reload watch and diagnostics implement explicit subsequent user requirements. They are not security hardening added by67.
